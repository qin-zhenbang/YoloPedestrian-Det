# 指标口径说明（T013）

本文说明 `results/tables/` 三份 CSV 的计算方法、真值来源和复核记录，供 PPT 引用与答辩备查。

## 1. 数据与真值

- 测试集：40 张，day / night / occlusion / crowd / small 各 8 张，来源登记见 `data/SOURCES.md`。
- 真值：`data/labels.csv` 的 `person_count`，每张图一个人工计数，不含逐人框。
- 稀疏图（人数 < 13）直接采用 COCO val2017 官方人工 person 标注核对；密集图逐排/逐区人工计数，估算值在 `labels.csv` 的 `note` 列标注：
  - `night_007` 约 160（看台约 150，±20）
  - `crowd_005` 约 165（百人合影，±10）
  - `crowd_002/003/004/007` 各 ±3，`crowd_006` ±5，`night_005` ±2
- 这些误差只影响对应场景的漏检率，不改变 `day / occlusion` 的结论。

## 2. 检测配置

全部参数来自 `configs/exp.yaml`，代码不写死：

- 模型：`weights/yolov8n.pt`，CPU，`imgsz=640`，`classes=[0]`（只保留 person）
- 基线：`conf=0.25`，`iou=0.70`
- 单图推理默认 `rect=True`（按原图比例补边）；`detect_batch` 逐张调用单图推理，保证批量与单图结果一致。

## 3. 指标定义

真值只有人数，不能做 IoU 匹配，因此采用图像级计数口径：

| 指标 | 定义 |
| --- | --- |
| 检出 TP | `min(检测数, 真值)` |
| 误检 FP | `max(检测数 − 真值, 0)` |
| 漏检 FN | `max(真值 − 检测数, 0)` |
| 检出率 recall | `ΣTP / Σ真值` |
| 漏检率 miss_rate | `ΣFN / Σ真值`，恒等于 `1 − recall` |
| 精确率 precision | `ΣTP / Σ检测数` |
| 误检率 fp_rate | `ΣFP / Σ检测数`，恒等于 `1 − precision` |

**口径局限（必须在 PPT 中说明）**：

1. 计数口径默认“多出来的检测框都是误检”，同一人被重复检测也会计入误检，因此精确率偏保守、但漏检率不受框位置影响。
2. 框位置错误（例如把电线杆框成人）不会影响检出/漏检，只要数量对得上就算“检出”，因此不能等价于 mAP。
3. 密集场景真值本身是人工估算，`night / crowd` 的漏检率应表述为“约 XX%”，不宣称精确到小数。

## 4. 阈值扫描（T010）

- 阈值 0.05–0.90、步进 0.05，共 18 档，见 `threshold_sweep.csv`。
- 实现方式：只在 `conf=0.05` 推理一次，再按各档阈值过滤检测框统计，避免重复推理；已验证 0.25 档与直接按 0.25 推理的基线完全一致。
- 注意 0.05 是配置规定的扫描下界，F1 在该端点最高（约 0.68），不代表更低阈值不会更好。

## 5. 计时口径（T011）

- 只统计 `results[0].speed` 的 preprocess + inference + postprocess，不含读图、画框、写 CSV。
- 预热 3 张不计，正式 20 张取均值，`torch.set_num_threads(1)`，测完恢复原线程数。
- 本机结果：yolov8n 约 110.8–117.5 ms/张；机器负载会影响结果（曾出现 146.9 ms），PPT 引用时注明“本机 CPU 实测”。
- 官方 yolov8s 128.4 ms 来自 ultralytics 文档的 COCO val / CPU ONNX 口径，**与本机 PyTorch 实测不可直接比较**，只作量级参照。

## 6. 复核记录（2026-11-19）

对三份 CSV 做结构与独立重算复核，全部通过：

- `threshold_sweep.csv`：18 行、阈值序列 0.05–0.90 正确；每行满足 `TP+FP=检测数`、`TP+FN=真值`，四个比率与公式一致；检测数随阈值单调不增。
- `scene_breakdown.csv`：5 个场景；合计 `gt=703, det=264, tp=249, fp=15, fn=454`；与阈值表 0.25 行完全一致。
- 独立重算：在 `conf=0.05` 重新推理后过滤，0.05 / 0.25 / 0.50 / 0.90 四档结果与 CSV 完全相同；五场景汇总也完全一致。
